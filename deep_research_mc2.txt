Executive SummaryThe extraction of market data from highly constrained, integer-scaled graphical user interfaces presents a distinct set of challenges that frequently neutralize traditional machine learning approaches. In the context of automating a market analysis and purchasing system—specifically, a Minecraft Auction Sniper Bot operating on the DonutSMP server—the legacy implementation relied on Google’s Tesseract Optical Character Recognition (OCR) engine to parse critical financial metrics from the game's rendering engine. This probabilistic approach resulted in catastrophic systemic failures. The neural network architecture of Tesseract proved fundamentally incompatible with the pixel-art typography of the Minecraft user interface, leading to the complete failure of quantity sprite extraction and severe data corruption in tooltip price parsing (such as hallucinating a hollow "0" as an "8", transforming a $120,000 listing into $128,888).This comprehensive research report outlines the theoretical foundation and practical implementation required to permanently eradicate the Tesseract OCR dependency, replacing it with a deterministic, mathematically verifiable computer vision pipeline utilizing OpenCV. By transitioning from a Long Short-Term Memory (LSTM) neural network to Normalized Cross-Correlation (NCC) template matching , the system achieves pixel-perfect data extraction. This analysis dissects the morphological properties of Minecraft’s Graphical User Interface (GUI) Scale 3, engineered a shadow-anchored binary masking technique to isolate text from item sprite glare, and constructs a robust One-Dimensional Non-Maximum Suppression (1D-NMS) algorithm to reconstruct multi-digit character strings. The resulting Python architecture provides the explicit codebase required to overhaul build_templates.py and scanner.py, ensuring faultless operation across the entire automated sniping pipeline.2. Diagnostic Analysis of Optical Character Recognition FailuresTo architect a flawless replacement pipeline, it is necessary to mathematically deconstruct why the probabilistic approach of the Tesseract engine failed within this specific graphical environment. Tesseract was designed for high-resolution, anti-aliased document scanning, where characters possess continuous edge flows and sub-pixel gradient boundaries.2.1. The Neural Network Hallucination PhenomenonThe primary data corruption event occurs during the extraction of tooltip prices. The Minecraft rendering engine generates tooltips as a dark, semi-transparent overlay. Price strings are typically rendered in the green format code §a, which corresponds to the precise hexadecimal value #55FF55 (RGB: 85, 255, 85). This text is accompanied by a directional drop shadow rendered in #153F15 (RGB: 21, 63, 21).When the scanner.py script captured this region and passed it to the Tesseract engine, the neural network attempted to evaluate the character structures using convolution filters trained on standard typography. A pixel-art "0" in Minecraft is constructed from rigid, one-pixel-wide vertical and horizontal strokes surrounding a hollow center. Because Tesseract relies on anti-aliasing to determine stroke weight and vector direction, the lack of sub-pixel blending in the Minecraft font causes the network's filters to misinterpret the rigid inner corners of the "0". The presence of the #153F15 drop shadow further confused the bounding box estimations. Consequently, the network mathematically perceived "bridges" across the hollow center of the digit, leading to the hallucination of an "8". No amount of image preprocessing—including Lanczos resampling, upscaling by a factor of three, or utilizing specific Page Segmentation Modes like PSM 8 (single word)—could reliably prevent the LSTM from enforcing document-based typographical rules onto rigid pixel matrices.2.2. Spatial Failure in Quantity Sprite ExtractionThe secondary failure vector occurred during the extraction of the item quantity strings. In the Minecraft UI, items are displayed within a 54x54 pixel slot array. When multiple items are stacked (e.g., 64 diamonds), the game engine renders a quantity sprite anchored to the absolute bottom-right corner of the 54x54 slot.The previous iteration of the scanner captured the top-left portion of the slot or attempted to read the entire 54x54 region prior to the mouse hover event. However, the digits are exceedingly small. Operating at the user's preferred GUI Scale 3, the native 5x7 pixel font sprites are scaled by a factor of three, resulting in a 15x21 pixel effective resolution per character. Tesseract requires a minimum pixel density and clear whitespace padding to establish text baselines. The extreme proximity of the digits to the 2-pixel pure white GUI slot bevel, combined with the visual interference from the underlying item sprite (such as the diamond icon), completely shattered Tesseract's baseline detection algorithms. The engine failed to distinguish between the graphical boundaries of the item and the structural boundaries of the numbers, returning empty strings or random character noise.2.3. Theoretical Framework for Deterministic Template MatchingTo achieve 100% accuracy, the probabilistic evaluation must be replaced with Normalized Cross-Correlation (NCC), implemented via OpenCV's matchTemplate function.4.1. The Mathematics of Normalized Cross-CorrelationThe cv2.TM_CCOEFF_NORMED algorithm evaluates the similarity between a template image $T$ and a source image $I$ by sliding the template across the source (similar to a 2D convolution). At each coordinate $(x, y)$, it calculates a correlation coefficient $R(x, y)$.$$R(x,y) = \frac{ \sum_{x',y'} (T'(x',y') \cdot I'(x+x',y+y')) }{ \sqrt{ \sum_{x',y'}T'(x',y')^2 \cdot \sum_{x',y'} I'(x+x',y+y')^2 } }$$In this equation, $T'$ and $I'$ represent the mean-subtracted patches of the template and the image, respectively. The normalization factor in the denominator ensures that the output score strictly bounds between -1.0 (perfect negative correlation) and 1.0 (perfect positive correlation).Because the Minecraft GUI is integer-scaled and lacks distortion, template matching against a properly binarized image will yield correlation scores approaching 1.0 for valid matches, and significantly lower scores (typically < 0.6) for mismatches (e.g., comparing a "3" against an "8"). This vast mathematical divide allows for the establishment of a highly reliable confidence threshold, virtually eliminating false positives.4.2. One-Dimensional Non-Maximum Suppression (1D-NMS)A known characteristic of sliding-window correlation is the generation of multiple, slightly offset bounding boxes around a single target. For example, a template perfectly centered over a digit might yield a score of 0.99, while shifting the template one pixel to the left might yield a score of 0.88. If the confidence threshold is set to 0.85, the algorithm will register multiple overlapping matches for the same character.To resolve this, the pipeline must implement Non-Maximum Suppression (NMS). Traditional NMS evaluates Intersection over Union (IoU) for 2D spatial objects. However, typographic strings in a UI are rendered on a strictly horizontal 1D plane. Therefore, a highly optimized 1D suppression algorithm is vastly superior. The algorithm sorts all matches by their correlation score in descending order. It iterates through the highest-scoring bounding boxes, suppressing any subsequent boxes whose X-coordinate origin falls within a specific horizontal threshold (e.g., 50% of the character width) of a confirmed, higher-scoring box.Once suppression is complete, the surviving bounding boxes are re-sorted ascendingly by their X-coordinates to geometrically reconstruct the integer string in the correct reading order.5. Engineering the Template Extraction Pipeline (build_templates.py)The first imperative of the architectural redesign is to solve Objective 1: establishing a flawless template extraction mechanism that perfectly isolates the 0-9 digits from raw page1_slotX_qty.png quadrant captures without capturing the pure white glare of the item sprite.5.1. Bypassing Glare via Shadow-Anchored Boolean LogicThe legacy build_templates.py failed because it relied entirely on a single parameter: white pixel intensity. To separate the quantity digits from the diamond glare, the new architecture will employ a dual-masking Boolean logic sequence that evaluates both the foreground color and its morphological shadow counterpart.Foreground Binarization: Extract all pure white pixels (R>200, G>200, B>200) to create Mask_W. This mask contains both the digits and the diamond glare.Shadow Binarization: Extract all dark drop-shadow pixels (R<65, G<65, B<65) to create Mask_S.Morphological Translation: Because Minecraft GUI Scale 3 renders shadows at a consistent geometric offset to the bottom-right, we can mathematically translate Mask_S up and to the left by the exact offset distance (e.g., -2 pixels X, -2 pixels Y).Boolean Intersection: Perform a bitwise AND operation between Mask_W and the translated Mask_S.Through this operation, a white pixel is only preserved if there was a corresponding black shadow pixel mathematically anchored to its bottom-right. Because the diamond glare is a flat texture with no localized drop shadow, it is entirely annihilated by the bitwise AND operation. The digits, possessing valid drop shadows, are perfectly preserved.5.2. Background-Independent Template GenerationThe second critical flaw in the legacy script was cropping the templates from the grayscale source image. A grayscale crop fundamentally includes the background texture (the slot coloring or item shading), which severely disrupts matchTemplate accuracy when deployed against different backgrounds in the future.The redesigned pipeline will crop the templates directly from the isolated binary mask. The resulting template library will consist of stark black backgrounds with pure white digit silhouettes, rendering the pattern-matching phase completely background-independent.5.3. class PatternMatchOCR:
    def __init__(self, templates_dir="templates"):
        self.templates = {}
        self._load_templates(templates_dir)

    def _load_templates(self, directory):
        """Loads binarized morphological templates into active memory arrays."""
        if not os.path.exists(directory):
            print(f"[!] Architecture Failure: Template directory '{directory}' missing.")
            sys.exit(1)
            
        for i in range(10):
            path = os.path.join(directory, f"{i}.png")
            if not os.path.exists(path):
                print(f"[!] Architecture Failure: Missing template '{i}.png'. Execute build_templates.py.")
                sys.exit(1)
            # Matrices must be loaded in grayscale to correspond with binary target planes
            self.templates[str(i)] = cv2.imread(path, cv2.IMREAD_GRAYSCALE)

    def extract_numeric_string(self, binary_img, threshold=0.92):
        """
        Executes Normalized Cross-Correlation across a binary plane.
        Resolves spatial overlaps using 1D Non-Maximum Suppression.
        """
        matches =
        
        # 1. Iterative Matrix Correlation
        for digit_char, tmpl in self.templates.items():
            h, w = tmpl.shape[:2]
            
            # Dimensional safeguard to prevent array broadcasting errors
            if binary_img.shape < h or binary_img.shape < w:
                continue

            # Compute similarity coefficient matrix
            res = cv2.matchTemplate(binary_img, tmpl, cv2.TM_CCOEFF_NORMED)
            
            # Isolate matrix coordinates exceeding confidence bounds
            locs = np.where(res >= threshold)
            for pt in zip(*locs[::-1]):
                score = res[pt, pt]
                matches.append([pt, pt, w, h, digit_char, float(score)])

        if not matches:
            return None

        # 2. One-Dimensional Non-Maximum Suppression (1D-NMS)
        # Prioritize coordinates by absolute mathematical confidence
        matches.sort(key=lambda x: x, reverse=True)
        
        suppressed_matches =
        for current_match in matches:
            x, y, w, h, digit, score = current_match
            is_overlapping = False
            
            # Evaluate spatial variance against verified boxes
            for confirmed in suppressed_matches:
                cx, cy, cw, ch, c_digit, c_score = confirmed
                # If X-coordinates origin shift is less than 50% of width, it is a localized duplicate
                if abs(x - cx) < (w * 0.5):
                    is_overlapping = True
                    break
            
            if not is_overlapping:
                suppressed_matches.append(current_match)

        # 3. Geometric String Reconstruction
        # Sort globally maximal bounding boxes ascendingly by X-axis coordinate
        suppressed_matches.sort(key=lambda x: x)
        
        # Assemble sequence; implicitly bypasses unregistered characters ($, commas)
        result_string = "".join([m for m in suppressed_matches])
        
        try:
            return int(result_string)
        except ValueError:
            return None

class AuctionScanner:

    def _load_geometry(self):
        """Ingests grid mathematics and dimensional offsets from config."""
        with open('config.json', 'r') as f:
            self.config = json.load(f)
        self.slots = self.config['slots']
        self.settings = self.config['scan_settings']
        self.slot_w = self.config['grid']['slot_width']
        self.slot_h = self.config['grid']['slot_height']

    def binarize_white_typography(self, img_np):
        """Isolates the white quantity text from slot sprites."""
        lower_bound = np.array()
        upper_bound = np.array()
        return cv2.inRange(img_np, lower_bound, upper_bound)

    def binarize_green_typography(self, img_np):
        """
        Isolates Minecraft §a green (#55FF55) tooltip prices.
        Eradicates gradient backgrounds and drop shadows.
        """
        # Strict RGB bounds to target foreground greens exclusively
        lower_bound = np.array()
        upper_bound = np.array()
        return cv2.inRange(img_np, lower_bound, upper_bound)

    def capture_cv2_frame(self, x, y, w, h):
        """Executes high-speed frame grab and converts MSS BGRA to OpenCV BGR."""
        monitor = {"top": int(y), "left": int(x), "width": int(w), "height": int(h)}
        frame = self.sct.grab(monitor)
        frame_np = np.array(frame)
        return cv2.cvtColor(frame_np, cv2.COLOR_BGRA2BGR)

    def extract_slot_quantity(self, slot_x, slot_y):
        """
        Captures the bottom-right quadrant of the 54x54 item slot prior to hover 
        and extracts the sprite quantity via pattern correlation.
        """
        # Ensure we capture the specific 27x27 bottom-right region defined in legacy attempts
        quadrant_w, quadrant_h = int(self.slot_w / 2), int(self.slot_h / 2)
        x_origin = int(slot_x)
        y_origin = int(slot_y)
        
        img = self.capture_cv2_frame(x_origin, y_origin, quadrant_w, quadrant_h)
        
        binary_plane = self.binarize_white_typography(img)
        return self.ocr_engine.extract_numeric_string(binary_plane, threshold=0.90)

    def extract_tooltip_price(self, cursor_x, cursor_y, row_index):
        """
        Captures the tooltip overlay, dynamically adjusting Y-axis offset 
        to account for Minecraft's bottom-row rendering inversion.
        """
        w = self.settings['tooltip_capture_width']
        h = self.settings['tooltip_capture_height']
        x = cursor_x - 20
        
        # Tooltips shift UP if hovering in bottom half of GUI grid
        y = cursor_y - 220 if row_index >= 3 else cursor_y - 50
            
        img = self.capture_cv2_frame(x, y, w, h)
        
        binary_plane = self.binarize_green_typography(img)
        
        # Suffix handling (K, M) requires localized checking if necessary,
